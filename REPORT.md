# Отчёт по лабораторной работе GitHub Actions

## Контрольные вопросы

### 1. Из каких элементов состоит workflow и как они вложены друг в друга?

Workflow описывается одним YAML-файлом в каталоге `.github/workflows/`. В нём задаются имя, события запуска и jobs. Каждый job выполняется на runner и содержит последовательность steps. Step либо запускает команду через `run`, либо использует готовый action через `uses`.

### 2. Чем job отличается от step?

Job — это отдельная задача, которая выполняется на своей виртуальной машине. Несколько jobs по умолчанию запускаются параллельно. Step — один шаг внутри job; шаги одного job выполняются последовательно и используют общую файловую систему этой машины.

### 3. Чем запуск по push отличается от запуска кнопкой workflow_dispatch?

`push` запускает workflow автоматически после отправки коммитов в подходящую ветку. `workflow_dispatch` запускается вручную кнопкой Run workflow во вкладке Actions и при необходимости может принимать входные параметры.

### 4. Как безопасно передать в workflow пароль или токен?

Пароль или токен нужно сохранить как GitHub Actions secret в настройках репозитория и обращаться к нему через `${{ secrets.ИМЯ }}`. Значение нельзя записывать в репозиторий или выводить намеренно в лог. GitHub маскирует совпадающее значение в журнале звёздочками.

### 5. Что такое артефакт и зачем он нужен?

Артефакт — файл или набор файлов, сохранённый во время запуска workflow. Он нужен, чтобы передать результат между jobs или скачать его после выполнения, например сборку, отчёт или журнал тестов.

### 6. Как заставить один job дождаться завершения другого?

Нужно указать зависимость `needs`, например `needs: build`. Тогда зависимый job начнётся только после успешного завершения указанного job.

### 7. Зачем нужен линтер, если есть тесты?

Тесты проверяют ожидаемое поведение программы на выбранных сценариях. Линтер отдельно находит ошибки синтаксиса, опасные конструкции и проблемы стиля, которые тесты могут не охватить. Вместе они дают более полную проверку.
